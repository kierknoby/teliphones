Development direction / Not a delivery promise

Earn reliability.
Then build on it.

Initial real connections matter. So does everything that happens when a session expires, a process fails or the firewall rebuilds. That is the next standard to meet.

A working foundation,
not a finished assurance case.

Windows 0.10.0 development source adds certificate-validated HTTPS administration through WireGuard using a scoped Microsoft Edge launch, plus improved tunnel lifecycle and recovery for TELIPHONES-owned resources. Recovery is independent of saved profiles, adapter-removal diagnostics are improved, unrelated VPN connections are protected, and uncertain cleanup is not treated as success. Windows error 1168 has not been definitively eliminated; its underlying cause remains unconfirmed.

The currently tested FreePBX module installation is 0.8.3.15, independently versioned from Windows. The Windows 0.10.0 target is unreleased; no build is available, and native build and acceptance tests remain outstanding. Open SSH currently uses the selected external terminal. The separate experimental built-in console is disabled on that path; its reported crash remains unresolved for that feature. Preserve existing published download links and version information until explicit approval.

First: close the validation gaps.

Validation outstanding

FreePBX module and real-PBX behaviour

Verify the currently tested 0.8.3.15 module installation, actual WireGuard roaming from unfamiliar public IPs, watchdog intervals and approved firewall rebuilds. Check Fail2Ban ordering and unchanged unrelated rules.

Exercise actual SIP calls, bidirectional RTP and unrelated management traffic throughout connection, rebuild, revocation and uninstall.

Validation outstanding

The entire session lifetime

Prove revocation and temporary authorisation expiry terminate owned PBX processes and leave empty cgroups, while unrelated SSH survives. Cover certificate refusal, lost reachability and client/server failure separately.

Validation outstanding

Restarts, upgrades and recovery

Test Windows/PBX reboots, broker restart, interrupted service operations, failed cleanup, upgrade, rollback and uninstall. Preserve original deadlines and an independent management route.

Windows native acceptance outstanding

The Windows and HTTPS service matrix

Build and test the exact Windows 0.10.0 source on a native Windows host. Verify certificate-valid hostname mapping and Edge launch over WireGuard, primary-service configuration, redirects, profile-free recovery, adapter removal and protection of unrelated VPN connections. Also exercise UAC, installation, scaling and monitor transitions. No 0.10.0 build or acceptance result is currently available.

Experimental / disabled on current path

The built-in console.
Source feature, not the active path.

The current Open SSH action launches the selected external OpenSSH-backed terminal after managed certificate issuance and host validation. The unreleased Windows source also contains an experimental in-process Custom Console with a libvterm-based screen model, interactive key encoding, UTF-8 handling, ANSI/cursor rendering, scrollback, clipboard actions and a ConPTY-backed OpenSSH resize path. This built-in console is explicitly disabled on the current managed SSH path.

Portable emulator tests cover VT output, keyboard input, UTF-8 chunking, resizing and scrollback. Earlier eleven-test native SSH success is operator-reported. Native MFC/ConPTY execution of the experimental console and the complete full-screen matrix remain unverified. A crash was reported when opening that embedded console; it remains unresolved for this experimental feature and is not a report about the selected external-terminal path. Do not treat earlier integration results as proof that the console issue is fixed.

Next: native verification

Build and exercise the experimental console's resize, disconnection, reconnect, UTF-8 and full-screen behavior on Windows against a disposable SSH host.

Keep the security boundary

Continue using the approved account, managed short-lived certificate, pinned host identity and owned session. A web-only workstation must request SSH elevation first; root is never implicit.

Planned development direction

Remote Support and
deployment maturity.

Improve the separate support workflow through complete end-to-end testing against explicit Connect, Checker and Console implementations. Verify expiry, cleanup and firewall reachability rather than assuming workstation success proves support success.

Deployment maturity includes reviewed packages, consistent source/build provenance, clear upgrade procedures and dependable recovery. It does not imply a hosted service, an engineer portal or universal NAT traversal already exists.

Rendezvous and relay ideas are documented separately as future design. They are not connectivity capabilities in the present product.

Useful contributions
make evidence reproducible.

Record exact versions, source revisions, build identifiers, test commands and sanitised outcomes. Distinguish operator observation from independently repeatable tests. Keep screenshots genuine and free of keys or customer data.

There are no promised release dates on this page. Goals may change as testing exposes constraints. Use the repository histories and evidence register for the implemented state, not the roadmap.
