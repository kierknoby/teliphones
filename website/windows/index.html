The right prerequisites.
No bundled VPN driver.

  • Windows 10 or 11, x64. Integrated WireGuard installation requires native Intel/AMD x64, not x64 emulation on ARM64.
  • Official WireGuard for Windows. Reuse a verified installation or explicitly approve the application's installer flow.
  • Windows system OpenSSH Client for managed SSH. GUI-only pairing does not need it.
  • A prepared FreePBX 17 / Debian 12 test PBX. Install the module and root broker, provide HTTPS for approval and make its WireGuard UDP endpoint reachable.

The Release build uses native C++17 Win32/MFC and static runtime linking. No .NET runtime or separate MFC/Visual C++ runtime is expected; Windows system components remain necessary.

Extract. Keep the helper.
Choose your tools.

Obtain the TELIPHONES-Windows-x64 artefact from an existing successful Windows Actions run. Extract the ZIP and keep TELIPHONES.exe and TELIPHONES-SSH.exe together. The helper is required for managed SSH.

The bundle includes licences and build-info.json with source/run provenance and executable hashes. Builds are unsigned; check their trusted origin rather than disabling SmartScreen or other protections.

  1. Applications

    Select a preferred browser and SSH terminal. Save & Next saves the selection; Skip retains the defaults.

  2. Secure connectivity

    Reuse verified WireGuard or choose Install WireGuard. TELIPHONES verifies a reviewed official MSI's pinned hash and Authenticode publisher, invokes Windows Installer through UAC and rechecks the installation.

  3. Get started

    Choose Add my PBX or finish and explore. Not Now never downloads software; return to Settings > Connectivity later. Connections require verified WireGuard.

Request access.
Then complete pairing.

  1. Enter workstation details

    Open Add my PBX... and enter the workstation name in Request access.

  2. Select requested access

    Choose FreePBX Web Access (default) or FreePBX Web + SSH Access. Web-only uses request v1 without an SSH identity; v2 adds its separate public identity. Neither choice grants authority.

  3. Generate and copy

    Select Generate request, then Copy request. Copy is disabled before generation. Changing name/access clears stale request/response data and requires regeneration, retaining the name.

  4. Open FreePBX

    A full administrator opens Connectivity > TELIPHONES > Pair a Workstation over trusted HTTPS.

  5. Complete the form

    Paste the request, set the reachable UDP endpoint, port, source policy and lifetime, and select SSH approval. SSH requires an SSH-capable request and an explicitly approved existing Linux account, never implicit root. Windows requires valid explicit SSH approval to save with Web + SSH selected. If the PBX approves web-only instead, generate a new Web Access request; the selected access is not silently downgraded.

  6. Copy the approved response

    Wait for the final pairing result. Progress only confirms liveness, not successful pairing. Copy the response from FreePBX.

  7. Paste in Windows

    Paste into Complete pairing. The validated response supplies the read-only approved SSH account, visible only when applicable; no manual value can override it.

  8. Validate and save

    Save connection enables only when the response matches the current request, endpoint, address, lifetime and SSH requirements; clicking Save revalidates. Invalid, old or mismatched responses remain rejected.

The pairing protocol remains compatible. The response envelope is request-bound, not independently signed: its provenance relies on trusted administrator HTTPS. SSH certificates are separately signature-verified.

Current module/broker 0.6.5 source adds durable revocation and verified removal. the local 0.6.5 archive and checksum include current source; the obsolete 0.6.4 archive was removed; historical archives lack those new security corrections. Live FreePBX acceptance is still required. Multiple PBX profiles can be saved, but only one tunnel is active. Do not publish pairing strings or keys.

Connect, then open FreePBX.

Select a profile and Connect. Approve the Windows tunnel setup when requested. The PBX grants a separate authenticated management-session lease; a WireGuard handshake alone does not count as an admitted session. The default capacity is one workstation. Once Connection Health reports the management endpoint reachable, select Open FreePBX and sign in with normal FreePBX credentials.

Windows 0.8.3 source retains and launches the approved HTTP/HTTPS URL, scheme and port, for example https://<PBX tunnel address>:8443/admin/. Standard 80/443 installations remain supported. Web redirects, listening addresses and TLS certificates remain a PBX configuration matter; do not bypass certificate checks to resolve a mismatch.

Unlocked pairings use the shared public WireGuard listener and may roam between public IPs. An administrator may instead approve a Locked pairing with a dedicated listener restricted to approved sources. Windows shows the actual PBX policy, current verified public source, DNS resolution failures, and session occupancy. Lock to Current IP uses the source observed by the PBX. Allowed List changes and unlocks are sent as requests and remain pending until an administrator approves them.

When an administrator changes listener mode, the existing WireGuard identity receives a bound configuration migration over its authenticated tunnel. The old path allows only session control until the updated tunnel acknowledges. If automatic migration is interrupted, reconnect the saved profile; do not delete the identity. Native Windows and live-PBX migration still require verification.

Custom-port import, launch and health checks require a build containing the current changes. Check build provenance as well as the unreleased 0.8.3 version. Re-pair saved profiles after changing the management URL on the PBX.

A built-in console.
Experimental, pending native validation.

With SSH explicitly approved and the PBX reachable, choose Open SSH. The unreleased Windows source opens the built-in console on the existing managed certificate, pinned host/CA identities and owned SSH process. A web-only workstation can choose Request SSH after pairing; FreePBX must explicitly approve the request and select an existing Linux account. There is no implicit root selection, password or unverified-host fallback. Rejection preserves web access.

The source now includes a libvterm-based VT screen, interactive keyboard input, ANSI colours and cursor control, scrollback, clipboard actions, reconnect/disconnect controls, and a ConPTY-backed OpenSSH path with terminal resize propagation. Portable emulator tests pass. Earlier operator reports confirm eleven native SSH integrations passed, including the production input/resize/disconnect path. They do not validate the current 0.8.3 source or the complete full-screen application matrix; those Windows checks remain outstanding.

Measurements, not reassurance by colour.

Connection Health now probes the saved management endpoint's TCP port: an explicit port such as 8080/8443, or HTTP 80 / HTTPS 443 when omitted. It no longer substitutes unrelated 443/80 probes for My PBXs. This measures a TCP connection, not HTTP contents, redirects or TLS certificate validity.

Graphs show recent jitter, application probe failures, byte-counter rates and handshake freshness. Three durations are distinct: Connected for, Authorisation remaining and continuously healthy time.

  • Choose latency/jitter, upload/download or failure/interruption graphs.
  • Pop out a compact monitor without stopping sampling when it closes.
  • Unknown measurements remain unknown; TCP failures are not network packet-loss measurements.
  • Management-endpoint degradation disables new SSH launches, but does not by itself close existing terminals.

Portable tests cover endpoint selection; native Windows execution of the updated custom-port path remains outstanding.

A timeline on each side

View Session Log shows local client observations and offers a text export. Logs are bounded, rotated and kept under the current user's local application data. The FreePBX module exposes a separately filtered PBX record to full administrators.

Review and sanitise exports before sharing them. Do not send private keys, credentials, complete pairing strings, grants or customer-identifying metadata.

Close the connection.
Or withdraw the permission.

Disconnect closes owned managed SSH processes and stops/removes the local tunnel. Normal application exit requests disconnection too. The pairing remains authorised, so reconnecting does not need a new approval while it is still valid.

Remove deletes the local profile and secrets. It does not revoke server-side authority or guarantee physical storage erasure. For a retired or lost workstation, revoke its pairing in FreePBX first.

Temporary approval retains its original expiry. Persistent approval lasts until revoked. No server-pushed revocation channel exists, so the Windows connection display is not a substitute for verifying PBX-side access removal.

Familiar tools.
Considered presentation.

Choose the Windows default browser or a detected Chrome, Edge, Firefox, Brave or Vivaldi installation. Settings can locate supported executables if detection misses them; a missing selection produces an explicit recovery choice, not a silent substitution.

System, Light and Dark appearance modes preview across TELIPHONES windows. Save persists the choice; Cancel restores it. Windows high-contrast settings take priority. Switching themes does not restart the tunnel or change authorisation.

The interface adapts its content to smaller and higher-DPI work areas, keeping connection actions available. Full real display-scale and multi-monitor validation remains part of the manual test programme.
