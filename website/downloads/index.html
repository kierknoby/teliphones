FreePBX / proposed 0.8.2 source

Firewall recovery.
Safe listener removal.

Proposed module and broker 0.8.2 retain protocol 12. The broker recognises the legitimate IPv4 NAT POSTROUTING hook and evaluates public unicast UDP listener traffic against applicable FreePBX 17 firewall rules, including chain traversal, source/interface conditions, marks, conditional jumps, returns and terminal rules. Irrelevant UDP, broadcast, multicast and DHCP rules are excluded; unsupported or ambiguous rules fail closed. Fail2Ban enforcement, safe workstation revocation/expiry and recovery after FreePBX Firewall regeneration are retained. Local regression tests have run, but PHP listener tests remain unexecuted in this environment and live connectivity is not established.

Development TGZ / PHP and live acceptance pending

TELIPHONES-0.8.2.tgz and its SHA-256 sidecar are prepared in the repository for controlled testing. They are not a public release, production-ready or live-accepted. The historical 0.6.7 archive and sidecar were intentionally removed from this checkout and did not contain these changes. The separate website ZIP is an older snapshot; its presence does not establish which source is deployed.

No installation on a live FreePBX 17 / Debian 12 host or public release is established.

Package availability does not authorize installation. Follow the repository's controlled-development upload and checksum instructions only when specifically authorized; do not publish a release package as part of source-preparation work.

A checksum establishes byte identity, not publisher trust or live readiness. Verify a candidate against its matching trusted sidecar. After installation, repeat the documented root bootstrap with no active support session and workstation tunnels disconnected.

Open Windows build workflow ↗Check Windows requirements

Artefact retention is 14 days. Check source revision, run identity/attempt and executable hashes in build-info.json; version text alone is insufficient.

  • Keep TELIPHONES.exe, TELIPHONES-SSH.exe and wireguard.dll adjacent.
  • Read the included licence files.
  • Inspect build-info.json provenance and executable hashes.
  • Expect unsigned test executables; verify trusted origin rather than disabling Windows protections.
  • Install/reuse official WireGuard separately; it is not bundled.

Native application validation remains outstanding. Opening the embedded SSH console unexpectedly closing TELIPHONES is an unresolved release blocker. GUI-only access needs no OpenSSH; managed SSH does.
